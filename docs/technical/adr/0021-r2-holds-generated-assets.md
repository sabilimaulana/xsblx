# 0021 — R2 holds generated assets, and the Worker serves `public/*`

## Context

Avatars are generated at registration and stored as SVG, with the URL on the row
(ADR 0018). On the VPS the store is SeaweedFS in compose, written with Bun's
`S3Client` and read anonymously through its S3 gateway because `public/*` carries
an anonymous grant.

On Cloudflare (ADR 0019) neither half survives as-is. Bun's `S3Client` is a Bun
API and does not exist in an isolate, and the store itself would either have to
stay on the VPS — chaining the edge deploy to a box it otherwise does not need —
or become R2.

R2's anonymous read path is not a prefix grant: a bucket is private unless it is
attached to a custom domain (or the `r2.dev` subdomain is enabled), and this stack
owns no zone.

## Decision

**Generated assets live in one R2 bucket, and the API Worker is the read path.**

- **One bucket, `Cloudflare.R2.Bucket("Assets")`, bound as
  `ReadWriteBucket`.** A new kind of asset is a new key prefix, never a second
  bucket. The name is generated by alchemy from stack, stage and logical id, so
  every stage gets its own.
- **`public/*` stays the convention, and is now enforced in code.** `GET
/public/*` on the API Worker streams the object whose key is the request path,
  after matching it against an allow-list pattern. Anything outside `public/` has
  no route and therefore no read path at all.
- **Writes go through the binding, not an S3 client.** Avatar generation still
  runs inside Better Auth's `databaseHooks.user.create.before`, outside the
  Effect runtime (ADR 0007), so it takes the native `R2Bucket` object from the
  binding's `raw` escape hatch and uses its promise API.
- **The stored URL is still absolute**, built from the Worker's own public URL
  (`Cloudflare.Worker.URL`) — the web app is a different origin, so a relative
  path would resolve against the wrong host.
- **This supersedes ADR 0018.** The decision it recorded — random seed, one
  bucket, prefix as the access rule, a failed upload leaves `image` null — is
  unchanged. Only the store and the read path are.

## Consequences

- **An avatar read costs a Worker invocation.** SeaweedFS answered those requests
  itself; now the isolate does. The response carries
  `cache-control: public, max-age=31536000, immutable`, and the key contains a
  fresh id per avatar, so Cloudflare's edge cache absorbs the repeats — but the
  first request per colo is a Worker call and a subrequest, and that is the
  trade for owning no zone.
- **The prefix rule is a regex, not an ACL.** SeaweedFS enforced `public/*` at
  the store; R2 enforces nothing here, because the bucket is private and the
  Worker is the only reader. The route's pattern is what keeps `private/*` from
  becoming readable by accident, so it is a trust boundary and belongs in a test
  before the second prefix exists.
- **Attaching a custom domain later rewrites the URL shape.** Stored URLs point
  at the Worker; serving assets from `assets.example.com` would point at R2
  directly. That is the same ceiling ADR 0018 recorded — an absolute URL on the
  row — and the same fix: store the key, join at read time, migrate once.
- **There are no S3 credentials any more.** `S3_ACCESS_KEY`, `S3_SECRET_KEY`,
  `S3_BUCKET`, `S3_ENDPOINT` and `S3_PUBLIC_URL` are gone from every `.env`, and
  the bucket needs no identity file, no init container and no bucket-create step.
- **`*.bun.test.ts` no longer exists.** The avatar test read objects back with
  Bun's client against a local store; both are gone, and the write path is
  covered by the end-to-end test's registration flow (ADR 0020). The vitest
  `exclude` for `*.bun.test.ts` was dropped with it.
- **Nothing deletes avatars, still.** A deleted user leaves its object behind. R2
  has lifecycle rules, which is a cheaper answer than the sweeper ADR 0018
  imagined — and still not written.
